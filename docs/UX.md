# UI/UX 設計(市場調査ベース)

調査日: 2026-09-19。PLAN.md の Phase 6〜9 の画面設計の入力になる。
**確認できた事実**と**私の設計判断**を区別して書く。

## 1. 調査対象と限界
対象: Sleep as Android、Sleep Cycle、SnoreLab、Pillow。加えて、睡眠アプリの UX ケーススタディと、Material 3 の公式ガイドライン。

**限界**: 私は実際の画面を見ていません。公式ドキュメント、ストア説明、レビュー記事のテキストから読み取れる範囲です。特に Sleep Cycle と Pillow は、ストア説明や記事の概要レベルにとどまります。**画面の見た目の最終判断の前に、各アプリのストア画像を自分の目で確認してください。**
また、**画面の構成やフローなどの「パターン」を参考にするだけで、他アプリの見た目(配色、アイコン、レイアウトの細部)は真似しません。**

## 3. 提案する構成

### ナビゲーション(下部タブ4つ)
| タブ | 内容 | 対応 FR |
|---|---|---|
| 計測 | 開始前の案内、「睡眠開始」 | FR-2 |
| Journal | 日ごとの結果一覧と、詳細(スコア、睡眠曲線、音イベント) | FR-4 |
| 統計 | 週/月の集計 | FR-5 |
| 設定 | プロフィール、目標、権限アシスタント | FR-8 |

### 計測中の画面(暗い全画面)
```
        02:14            ← 現在時刻(大きく、控えめな明るさ)
    ● 録音中  3時間12分   ← 経過時間

     [ 長押しで終了 ]      ← 誤操作防止。押し続けると輪が満ちる
```
- 最低限の情報だけ。輝度は最小に。
- 終了は**長押し**(約1.5秒)で確認を通し、その後に Phase 1 で作る「Discard / Short Sleep として保存 / 継続」の選択を表示する。
- 画面モード(FR-2.3)の3つ(自動ロック、暗く、時計付きで暗く)は、開始前に選ぶ。

### 結果画面(Journal の詳細)
```
 ┌───────────────────────────┐
 │  スコア 82  Pretty Good     │
 ├───────────────────────────┤
 │  睡眠曲線 + 音量グラフ(同軸)│  ← タップでその時刻の音を再生
 │  ▲いびき ▲咳 ▲寝言 マーカー │
 ├───────────────────────────┤
 │  指標カード: 睡眠時間 / 効率 / 覚醒回数 / 入眠潜時 │
 ├───────────────────────────┤
 │  いびき: 頻度・強度区分         │
 │  音イベント一覧(再生・再分類・削除) │
 └───────────────────────────┘
```

### 波形の扱い(決定)
- **計測中は、波形もレベルメーターも表示しない。** 暗い最小画面(時刻、経過時間、録音中の表示)を優先する。
- **一晩の音量グラフ**: 結果画面のタイムラインに、1秒ごとの平均・最大 dB を描く(Phase 2 のデータを使用)。
- **クリップ単体の波形**: イベント詳細の再生画面に、波形と再生位置を表示する(Phase 7)。WAV から最大値を間引いて Canvas で描く。
- 録音が動いていることの確認は、**通知の経過時間(Phase 0 で実装済み)**と、開始直後のエラー表示で行う。

## 4. 参考にしないこと
- Sleep as Android は、設定が非常に多く、初心者には複雑。**設定項目は必須のものに絞る。**
- 計測中のリアルタイム波形は、電池消費と画面の明るさの面から採用しない。
- 心拍、SpO2、光センサーなどのセンサー系のグラフは対象外。
- 動画共有や、装飾的なアニメーションは後回し(SPEC の FR-3.5、4.8 の一部)。

## 5. 実装時の方針
- Material 3 の標準コンポーネントを基本にし、グラフだけ Canvas で自前描画する。
- 色はトークン(`MaterialTheme.colorScheme`)経由にして、後から差し替えやすくする。
- 文字は大きめ、コントラストは高めにする。ただし夜間は、白い文字ではなく、少し暗めのグレーを使う。
- 文言は、Phase 9 で多言語化しやすいよう、最初から `strings.xml` に置く。

## 6. 追加調査: ストア説明とユーザーレビュー(2026-09-19)
対象: [Sleep Tracker & Snore Log(すりーぷまいすたー)](https://play.google.com/store/apps/details?id=sleeptrakcer.sleeprecorder.sleepapp)、[SnoreLab](https://play.google.com/store/apps/details?id=com.snorelab.app)(いずれも Play ストア日本語版)。

**限界**: 取得できたのは、ストアの説明文と、SnoreLab のレビュー約20件です。スクリーンショットは見ていません。**すりーぷまいすたーのレビューは取得できませんでした。** レビューは自発的な投稿なので、不満は実際より多く見えます。傾向をつかむ目的で使います。

### 6-1. すりーぷまいすたー(Sleep Tracker & Snore Log)
説明文から分かる機能構成は次のとおり(画面構成は不明)。
- 睡眠トラッカー(睡眠時間、質、就寝スケジュール、規則性)、日次レポート、週次サマリー、月次分析。
- いびき・寝言・寝室の音・周囲の音の自動録音。
- 睡眠日記(就寝前ルーティン、日々のメモ、朝の気分)。
- スマートアラーム、睡眠サウンド。
- 「すっきりしたインターフェース」「軽量設計」をうたっている。
- 広告表示とアプリ内課金あり。

**示唆**: 機能の組み合わせは、SPEC の必須範囲(計測、いびき・寝言の録音、日次/週次/月次、朝の気分、メモ)とほぼ一致します。**この範囲が、市場で標準的な構成**だと確認できました。

### 6-2. SnoreLab のレビューから読み取れること
| 種類 | 内容(レビューの要旨) | 設計への反映 |
|---|---|---|
| 好評 | 起動して枕元に置くだけで、一晩の音が取れる | 開始までの操作を最小にする(§3 の計測画面) |
| 好評 | いびきが激しい箇所を**タップして聞ける** | 採用済み。タイムラインからの再生を主な入り口にする |
| 好評 | **気になる部分だけをピックアップして保存**できる | Phase 3 のクリップ保存の方針と一致 |
| 好評 | **「一時停止」**ボタンで、夜中に起きたときに止められる | 計測中に、一時停止を追加する(§3 に反映) |
| 好評 | **計測開始の遅延**を指定できる(BGM をかけてから、30分後に計測など) | 任意機能として候補。FR-2.6(スリープサウンド)の拡充フェーズで検討 |
| 好評 | 睡眠時間の合計が表示される | 結果画面の指標カードに含める |
| 不満 | **アイコンの意味が分かりにくい**(表示変更後) | アイコンだけにせず、必ずラベルを付ける |
| 不満 | **無呼吸の部分が録れない**。「○秒無音なら録音を残す」機能が欲しい | Phase 4 の無呼吸候補(いびき後の無音区間)の方針が妥当。**無音区間の前後をクリップとして残す** |
| 不満 | 寝返り、車、テレビにも反応して録音される | 誤検出は現実の問題。Phase 3〜4 で閾値と分類の検証を重視する |
| 不満 | 機種変更後、**再生音が極端に小さい** | クリップ再生に、音量の正規化(ゲイン補正)を入れる |
| 不満 | 充電しながら寝ると朝にスマホが固まる/「マイクのデータが読めない」エラーで**朝には停止していた** | 中断の検知と朝の案内(FR-2.9)は重要。**録音失敗を、ユーザーが朝に必ず気づける**ようにする |
| 不満 | スタート直後に解除され、計測されていない | **開始後の状態を、はっきり見せる**(計測中の表示、通知)。失敗時は即エラー表示 |
| 不満 | 5日使うと2日ロックされる、強制動画広告、有料化への誘導 | 個人用なので課金はないが、**無料枠のロックのような信頼を損なう作りは避ける**という教訓 |
| 不満 | 分析だけで、対処の提案がない | Tips(FR-4.9)は後回し。現時点は対象外 |
| 不満 | 取扱説明がなく、使い方が分かりにくい | 初回の案内(オンボーディング)と、置き場所の説明に力を入れる |
| 中立 | スマホの置き場所で結果が大きく変わる | 開始前の案内に、置き場所の具体例を載せる(FR-2.4)。「布団の上に伏せて置く」などの声もあり、**端末の向きと位置は、実機で試して推奨を決める** |

### 6-2b. 録音を聴くことは中核の機能(見直し)
- すりーぷまいすたーの説明: 「毎朝録音を聞き、睡眠中に何が起こっているのかをより深く理解しましょう」。
- SnoreLab の説明: 起床時に、いつ・どれだけ大声でいびきをかいたか、ハイライトを確認する。
- SnoreLab のレビュー: 「タップすると音を聞ける」「一晩中取れていた」「全てを聞けないのが不満」「再生音が小さい」。
- 当初の計画では、再生を Phase 7 に置いていた。これは遅すぎたため、クリップができる Phase 3 の直後(Phase 3.5)に前倒しした。
- 再生の単位は、一晩まるごとではなく、**イベントのクリップ**にする(容量のため。全録音は既定でオフ)。

### 6-3. 設計への反映まとめ
§3 の構成に、次を追加・修正する。
1. **計測中の画面に、一時停止を追加する。** 長押しで終了、一時停止は通常タップ。
2. **アイコンにはラベルを付ける。** 下部タブも、結果のマーカーも、凡例を出す。
3. **無呼吸の候補クリップは、無音区間の前後を含めて保存する。**
4. **クリップの再生に、音量の正規化を入れる。**
5. **計測の失敗や中断を、朝に確実に伝える。** 通知と、起動時のダイアログの両方を使う。
6. **開始の遅延タイマー**は、優先度の低い任意機能として、拡充フェーズに置く。
