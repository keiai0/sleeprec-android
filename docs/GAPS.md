# ヌケモレ調査: 類似アプリで標準の機能と、技術前提

調査日: 2026-09-19。SPEC.md と PLAN.md に対して、抜けている項目を洗い出した。
**確認度**の凡例: ◎ 公式ドキュメントで確認 / ○ 比較記事・ストア説明・レビューで確認 / △ 私の判断(根拠は弱い、または一般論)。

**調査した範囲の限界**: 公式ドキュメント(Sleep as Android、Android Developers)、ストア説明、日本語の比較記事、SnoreLab のレビュー約20件。Sleep Cycle と Pillow の詳細な機能一覧、すりーぷまいすたーのレビューは取得できていない。

## A. 技術前提(修正が必要なもの)

| ID | 内容 | 確認度 | 優先度 |
|---|---|---|---|
| A1 | **targetSdk が最新ではない。** 公式の API レベル表で、最新の安定版は **API 37(Android 17)**。現在は 36 で、要件「targetSdk は最新」を満たしていない([出典](https://developer.android.com/guide/topics/manifest/uses-sdk-element)) | ◎ | **高** |
| A2 | 37 に上げるには、**AGP 9.4.x**(API 37 に対応した最初の版)、**Gradle 9.6.0 以上**、JDK 17、Kotlin プラグイン 2.2.10 以上が要る([出典](https://developer.android.com/build/releases/gradle-plugin))。現在は AGP 8.9.1 / Gradle 8.11.1 / Kotlin 2.1.20 なので、**AGP のメジャーアップグレード(8→9)**になる。Room、KSP、Compose のバージョンも合わせて確認が要る。AGP 9 での Kotlin プラグインの扱いなど、私は詳細を確認していない。Android Studio の AGP アップグレードアシスタントと、公式の移行ガイドで確認する | ◎(バージョン)/ △(移行の詳細) | 高 |
| A3 | **エッジ・ツー・エッジ(画面いっぱい表示)が強制される。** Android 15 以降、targetSdk 35 以上で強制。36 以上では opt-out も無効([出典](https://developer.android.com/about/versions/16/behavior-changes-16))。現在の画面は、システムバーの余白(insets)を処理していないので、Android 15 以降の端末では、内容がステータスバーやナビゲーションバーに重なる可能性がある。**あなたの端末(ColorOS 14 = Android 14)では再現しない**ため、気づきにくい | ◎ | 中 |
| A4 | **Android 17 のバックグラウンド音声の制限**([出典](https://developer.android.com/about/versions/17/changes/bg-audio))。対象は、音声の再生、オーディオフォーカス、音量変更で、**マイク録音の制限は明記されていない**。ただし、targetSdk 37 では、バックグラウンドでの再生に、while-in-use のフォアグラウンドサービスが必要。**録音は、現在の設計(アプリが前面のときにサービスを開始)で問題ない。Phase 3.5 の再生は、画面が前面にあるときに限れば影響なし。画面オフのまま再生(FR-6.4)するなら、サービスが要る** | ◎ | 中(拡充時に影響) |
| A5 | **マイクのフォアグラウンドサービスは、バックグラウンドから開始できない**。通知の操作などの例外があっても、while-in-use の権限が要るサービスは作れない([出典](https://developer.android.com/develop/background-work/services/fgs/restrictions-bg-start))。市場では「自動計測」(Sleep as Android など)が標準的な機能だが、**この端末では実現できない**。代わりに、就寝リマインダーの通知から、アプリを開いて1タップで開始する形にする | ◎ | 情報 |
| A6 | **通話などで、マイクが無音化される。** 通話中はシステムが AudioRecord の入力を無音にする。`AudioRecordingCallback` の `isClientSilenced()` で検知できる([出典](https://developer.android.com/media/platform/sharing-audio-input))。今の `WavRecorder` は、無音化されても、無音データを書き続けて、気づかない | ◎ | **高** |

## B. 機能のヌケモレ(市場で標準、または重要なもの)

|---|---|---|---|---|---|
| B1 | **クリップの保持ポリシー**: 未スターのクリップを一定期間(例 7日)で自動削除、お気に入り(スター)の保存、1晩の保存数の上限 | Sleep as Android は、スターなしのクリップを7日後に自動削除し、スターしたものを「Best of sleep」アルバムに書き出す。SnoreLab は既定で1晩20サンプル([Sleep as Android](https://sleep.urbandroid.org/docs/sleep/sleep_noise_recording.html)、[SnoreLab](https://www.snorelab.com/how-snorelab-works)) | ◎ | **高**(容量を抑える方針と直結) | Phase 3, 3.5 |

## C. SPEC 自体の食い違い・未定
- **FR-8.5(Google サインインのバックアップ)** と **NFR-3(録音はローカル保存、`allowBackup=false`)**: 何をバックアップするかが決まっていない。設定と統計だけにして、録音は対象外にするのが妥当。**要確認**。
- **FR-1.3(ストレージ権限)**: アプリ専用領域では不要。エクスポート機能(B7)を作る段階で、保存先によって必要性を再検討する。

## D. 確認できたこと(問題なし)
- **SPEC の必須範囲は、市場の標準構成と一致している**(すりーぷまいすたーの説明と、比較記事の表から)。いびき・寝言の録音、睡眠のグラフ化、週/月の統計は、標準的な機能。
- 音を分類して、種類のタグ(#snore、#talk など)で管理する方式は、Sleep as Android と同じ考え方。Phase 4 の設計と合っている。
- 起動時に、フォアグラウンドサービスを画面が前面のときに開始する現在の設計は、Android 17 の制約にも合っている。
